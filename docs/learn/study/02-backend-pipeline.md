# Study Module 2 — Backend Architecture & Intelligence Pipeline

> Textbook notes on `server/` (Go/Gin). Anchored to verified source files. Companion to the
> production whitepaper and to Study Module 1 (ML). Read the code while reading this.

## 2.1 System shape

A Gin HTTP service plus a WebSocket hub, a SQLite store, an in-memory heatmap aggregator, and a
set of **integration workers** that pull public feeds and normalize them. Module path:
`Geospatial-harmuz-watch`.

> Source: `server/cmd/main.go`, `server/internal/api/handlers.go`.

## 2.2 The per-track pipeline (what actually runs)

Traced from `server/internal/integrations/aisstream.go` (representative worker — ADSB is similar):

```
AIS message
  └─ heatmap.AddTelemetry(lat, lon)                      // accumulate density grid
  └─ tsm.Update(...)  → ComputedDeltas                   // EWMA kinematic state per track
  └─ intelligence.ExtractFeatures(...) → FeatureVector   // + geofence + historical attack + Haversine
  └─ ruleScore  = anomaly.Score(...)                     // transparent rule score 0–100
  └─ mlScore, explanation = mlClient.Predict(features)   // → ml-service (IF+LOF+SHAP)
  └─ geoScore   = intelligence.GeoStore.ScoreForLocation // geopolitical event density
  └─ assessment = intelligence.ComputeComposite(...)     // 0.4·Rule + 0.4·ML + 0.2·Geo
  └─ broadcast "telemetry" + (if score>0) "anomaly"
  └─ persist to SQLite (tracks, anomalies)
```

This is the **real** scoring path — note it is *more* than the ML service alone: rule + ML + geo
are fused server-side so every client sees the same verdict.

## 2.3 Rule score — `anomaly.Score` (verified formula)

Inputs: `courseDelta, aisGapMinutes, speed, previousSpeed, distToZone, inRestrictedZone, nearHistoricalAttack`.
Output: integer 0–100.

| Factor | Condition | Points (max) |
|--------|-----------|--------------|
| Course deviation | `courseDelta > 10°` | ramps `0→34` over `10°→90°` |
| AIS staleness | `aisGapMinutes > 5` | ramps `0→26` over `5→30 min` |
| Speed drop | `previousSpeed − speed > 2 kt` | ramps `0→22` over `2→15 kt` |
| Excessive speed | `speed > 25 kt` | ramps `0→11` over `25→40 kt` |
| Restricted zone | `inRestrictedZone` | `+30` (else `<0.3°` away → up to `+15`) |
| Historical attack | `nearHistoricalAttack` | `+15` |

Capped at 100. All ramps are linear: `score += min(cap, (x−lo)/(hi−lo)*cap)`.

**Severity bands** (same function, reused by composite):

$$
\text{score} \ge 75 \Rightarrow \text{critical},\quad
\ge 55 \Rightarrow \text{high},\quad
\ge 30 \Rightarrow \text{medium},\quad
\text{else low}.
$$

> Source: `server/internal/anomaly/scorer.go`. This is the transparent, auditable score the
> publication quotes. Reasons/actions are generated by `GetReasons`/`GetActions` from the same
> inputs.

## 2.4 Composite — `intelligence.ComputeComposite` (verified)

$$
\text{FinalScore} = \big\lfloor 100 \cdot \mathrm{clip}_{[0,100]}\big(
0.4\,\text{Rule} + 0.4\,\text{ML} + 0.2\,\text{Geo}
\big)\big\rceil
$$

All three inputs are clamped to $[0,100]$ before weighting. Severity is then derived from
`anomaly.SeverityLevel(FinalScore)`.

> Source: `server/internal/intelligence/composite.go` (`WeightRule=0.4, WeightML=0.4,
> WeightGeopolitical=0.2`). Compare with the frontend `learn/anomaly.tsx` "Risk Score
> Calculation" panel, which shows a *different* weighting (40/20/15/15/10) — that panel is
> illustrative editorial content, not the backend formula. Keep this distinction clear in docs.

## 2.5 Features — `intelligence.ExtractFeatures`

Builds a 14-field `FeatureVector` from computed deltas + geospatial context:

- Kinematic: `CourseDelta, HeadingDelta, SpeedDelta, AverageSpeed, SpeedVariance, EWMADeviation`.
- Signal: `AISGapMinutes`.
- Geospatial: `DistToRestrictedZone, DistToHistoricalSite, InRestrictedZone, NearHistoricalAttack, RestrictedZoneName`.
- State: `Speed, PreviousSpeed, Lat, Lon`.

`EWMADeviation` is a z-score of the current kinematic state vs the per-track exponential weighted
moving average — a lightweight temporal model the ML service does not see.

Distances use **Haversine in nautical miles** (`geo.HaversineNM`); zone "distance" subtracts
`RadiusDeg*60` NM.

> Source: `server/internal/intelligence/features.go`. Note this schema is yet another feature
> representation (distinct from both ML schemas in Module 1 §1.8) — a known consolidation task.

## 2.6 Geofence & historical attacks

- `anomaly.CheckGeofence(lat,lon)` → `(inZone, zoneName)` against restricted-zone polygons.
- `api.IsNearHistoricalAttack(lat,lon)` → within a ~0.1° (~6 NM) proximity threshold.
- `intelligence.GeoStore` accumulates GDELT events as a danger-density surface
  (`ScoreForLocation`).

> Source: `server/internal/anomaly/geofence.go`, `server/internal/api/*` (historical attacks),
> `server/internal/intelligence/geopolitical.go`.

## 2.8 API surface (verified in `server/cmd/main.go`)

Two groups:
- **Public (no auth):** `GET /public/top-traces`, `GET /public/stream` (SSE), `GET /public/metrics` (API-key).
- **Auth (JWT):** `/vessels`, `/aircraft`, `/tracks/active`, `/history/attacks`, `/zones/restricted`,
  `/news`, `/heatmap`, `/watchlist`, `/settings`, `/telemetry`, `/analyze`, `/ws/stream`, `/stream/poll`, `/auth/*`.

> **Mismatch to fix (TODO m4 / P8):** `client-v2/src/lib/api.ts` calls `/public/history/attacks`,
> `/public/zones/restricted`, `/public/news`, `/public/heatmap`, but the server only registers
> those under the **auth** group (no `/public/` prefix). Public pages can't load zones/news until
> reconciled. Also `useAuthStore` calls `/api/v1/auth/*` but server routes are `/auth/*`.

## 2.9 Storage & real-time

- SQLite (`internal/db`): `tracks`, `anomalies`, `news`, `watchlist`. Raw SQL, bound params.
- `heatmap` aggregator: in-memory grid by source (vessel/fire/geo/all).
- WebSocket hub: broadcasts `telemetry`/`anomaly` messages; `WebSocketStream` hydrates clients
  from SQLite (last 2h) on connect.

> Source: `server/internal/api/handlers.go`, `server/internal/heatmap/*`, `server/internal/websocket/hub`.
